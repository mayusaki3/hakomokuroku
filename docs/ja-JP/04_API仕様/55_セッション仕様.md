# セッション仕様（Session Cookie 仕様）

ログイン済みユーザーの認証は、**セッションIDをブラウザCookieで管理する方式**を採用する。
本書では Cookie の形式、属性、ライフサイクル、エラー時動作を定義する。

---

# 1. Cookie 名称と形式

## 1.1 Cookie 名

```text
hakomokuroku_session
```

## 1.2 セッション値

- ランダムな 32〜64 byte の文字列（実装側で生成）
- DB の `Session` テーブル（仮想モデル）に紐づく

※ Prisma モデルは未定義だが、実装側ではセッション→ユーザーIDが解決される前提。

---

# 2. Cookie 属性（本番環境）

| 属性 | 値 | 説明 |
|------|------|------|
| HttpOnly | true | JavaScript から参照不可 |
| Secure | true | HTTPS 接続時のみ送信 |
| SameSite | Lax | CSRF 対策として Lax を採用 |
| Path | / | 全 API で共通利用 |
| Max-Age | 7日 | 再ログインによる延長あり |

開発環境では Secure を外せるが、**Path / HttpOnly は固定**とする。

---

# 3. セッション発行タイミング

## 3.1 通常ログイン成功時

```json
POST /api/auth/login
{
  "ok": true,
  "user": { ... }
}
```

- この時点で `Set-Cookie: hakomokuroku_session=<id>` を返す。

## 3.2 TOTP 必須ユーザーの場合

```json
{
  "ok": true,
  "totpRequired": true,
  "loginId": "xxxx"
}
```

- **Cookie は発行しない**
- `/api/auth/login/totp` に進む

## 3.3 TOTP 検証成功時

- `/api/auth/login/totp` が成功した時点で Cookie を発行する。

---

# 4. セッションの有効期限

### 4.1 有効期間
- **最終アクセスから 7 日**
- API へアクセスがあるたびに延長してよい（Rolling Session）

### 4.2 無効化されるタイミング
- `/api/auth/logout` 実行時  
- 不正な Cookie 値が送信された場合（内部的に削除して 401 を返す）

---

# 5. セッション検証（/api/auth/me）

### 5.1 セッションが有効な場合
```json
{
  "ok": true,
  "user": { ... }
}
```

### 5.2 セッションが無効 / 存在しない場合
```json
{
  "ok": false,
  "error": "unauthorized"
}
```

HTTP ステータスは `200` とする（既存仕様に合わせる）。

---

# 6. ログアウト時の仕様

`/api/auth/logout` は以下を行う：

1. セッションIDを無効化（DB または内部ストアから削除）
2. **空Cookieを Set-Cookie**  
   - Max-Age=0  
   - Path=/  

```text
Set-Cookie: hakomokuroku_session=; Max-Age=0; Path=/; HttpOnly; Secure; SameSite=Lax
```

---

# 7. テスト観点

1. Cookie が発行されるのは **通常ログイン成功 / TOTP成功時** のみ  
2. TOTP 未完了ログインでは Cookie は絶対に発行しない  
3. `/api/auth/me` は Cookie の有無で分岐し、401 ではなく `ok:false` を返す  
4. /logout 実行後は Cookie が削除される  
5. Rolling Session の確認（任意項目）
