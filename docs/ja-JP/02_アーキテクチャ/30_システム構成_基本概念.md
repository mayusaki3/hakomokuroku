# システム構成 / 基本概念

## 1. 箱目録とは

箱目録は、**どこに何があるのかを把握し、必要なものを迷わず取り出せるようにする**ためのシステムである。

そのため、少なくとも次の問いに答えられることを基本とする。

1. **この箱には何が入っているか？**
   - Box（箱情報）から、その中のItem（物品情報）を確認する。
2. **この物品はどの箱に入っているか？**
   - Itemから収納先のBoxを確認する。
3. **この箱はどこにあるか？**
   - BoxからBoxLocation（箱の場所情報）を確認する。
   - Boxが別のBoxに入っている場合は、親Boxをたどって実際の場所を確認する。
4. **この場所には何があるか？**
   - BoxLocationから、そこにあるBox、その中のBoxやItemを確認する。

これらは独立した機能ではなく、必要な物品へたどり着くための一連の情報として扱う。

例えば、

```text
探している物品
  ↓
Item（物品情報）
  ↓
Box C（箱情報）
  ↓
Box B（箱情報）
  ↓
Box A（箱情報）
  ↓
BoxLocation「押入れ」
```

のように、物品から実際の保管場所までたどれる。

逆にBoxLocationからBox階層をたどり、その場所に何が保管されているかを把握できる。

箱にはQRラベルを付け、実物の箱からBox情報へ直接アクセスできる。

## 2. 利用者

1つの箱目録システムを複数のUser（利用者）が利用できる。

各Userの業務データは他のUserから分離する。

```text
箱目録システム
  ├─ User A
  │    └─ User A のデータ
  ├─ User B
  │    └─ User B のデータ
  └─ User C
       └─ User C のデータ
```

同じID値が別Userのデータに存在しても、別のデータとして扱う。

## 3. デバイス

1人のUserは複数のDevice（デバイス）を利用できる。

例:

- PC
- スマートフォン
- タブレット

```text
User（利用者）
  ├─ Device（PC）
  ├─ Device（スマートフォン）
  └─ Device（タブレット）
```

同じUserのDeviceは、同期によって同じ業務データを扱う。

DeviceはBoxの所有者ではない。Box / Item / BoxLocationはUserに属する。

Device固有情報は、複数Deviceがofflineでも安全にBox.code（箱コード）を発行するための名前空間管理などに使用する。

詳細は [Box.code（箱コード）/ Device（デバイス）設計](./70_BoxCode_Device設計.md) を参照。

## 4. 管理対象

### 4.1 Box（箱情報）

物品を収納する箱を表す。

主な情報:

- 箱コード
- 箱名
- 箱の場所
- 親Box
- タグ
- メモ
- 写真

Boxは別のBoxの中へ入れることができる。

### 4.2 Item（物品情報）

管理対象となる物品を表す。

主な情報:

- 物品名
- 入っているBox
- タグ
- メモ
- 写真

ItemはBoxに入っていない状態も持てる。

### 4.3 BoxLocation（箱の場所情報）

Boxを置く物理的な場所を表す。

例:

- 押入れ
- クローゼット
- 倉庫
- 部屋

BoxLocationはItemの場所を直接表さない。

Itemの場所は、Itemが入っているBoxとBoxの配置関係から求める。

## 5. 基本関係

```text
User（利用者）
  │
  ├─ Device（デバイス） 1..N
  │
  ├─ BoxLocation（箱の場所情報） 0..N
  │      │
  │      └─ Box（箱情報）
  │            │
  │            ├─ Item（物品情報）
  │            │
  │            └─ Box（箱情報）
  │                  └─ ...
  │
  └─ 未割当
         ├─ 場所が未設定のBox
         └─ Boxに入っていないItem
```

BoxはBoxLocationへ直接置くことも、別のBoxへ入れることもできる。

ItemはBoxへ入れる。

## 6. Box（箱情報）のネスト

Boxは別のBoxの中に収納できる。

例:

```text
押入れ
  └─ Box A
       └─ Box B
            └─ Item
```

Box B自身はBoxLocationを直接持たない。

Box Bの実効的な場所は、親BoxをたどってBox AのBoxLocation「押入れ」から求める。

固定のネスト段数は設けないが、循環参照は禁止する。

## 7. 未割当

`UNASSIGNED` は「未割当」という論理状態を表す名称であり、BoxやBoxLocation等の実レコードではない。

DB/APIでは未割当参照を `null` で表現する。

主な未割当状態:

- ItemがどのBoxにも入っていない
- top-level Boxの物理的な場所が設定されていない
- Boxが他のBoxに入っていない

文字列 `"UNASSIGNED"` をentity IDとして保存しない。

## 8. Box.code（箱コード）とQR

各Boxは作成時にimmutableなBox.codeを持つ。

Box.codeはQRラベルにも使用する。

QR payloadはBox.codeそのものとする。

Deviceの変更、Backup / Restore、同期等によって既存Box.codeを自動変更しない。

詳細は [Box.code（箱コード）/ Device（デバイス）設計](./70_BoxCode_Device設計.md) を参照。

## 9. 複数Deviceとoffline利用

各DeviceはUser専用のローカルDBを持ち、通信できない状態でも業務データを扱える。

通信可能になった時点でserver canonical dataと同期する。

同期の詳細は [同期モデル](./50_同期モデル.md) を参照。

## 10. Backup / Restore

Userの業務データはバックアップファイルへ保存し、同じUserの環境へRestoreできる。

Device固有の名前空間やLocalSequence等は通常バックアップ対象に含めない。

詳細は [バックアップ / リカバリモデル](./60_バックアップ_リカバリモデル.md) を参照。

## 11. データ構造

Box / Item / BoxLocation等のfield、identity、DB constraint、同期補助schemaは [データモデル / DBスキーマ定義](./40_DBスキーマ定義.md) を参照。
