# Data Model設計

## 1. Identity / User boundary
Business identityは `(User.id, entityId)`。異なるUserは同じentityIdを持てる。serverはpayloadのuserIdを信用せずauthenticated Userからscopeを決定する。

参照は同一User内に限定する。

## 2. Business entity
### Box
- User scoped
- immutable `code`
- `locationId` でBoxLocationを参照
- reserved `UNASSIGNED` を持つ

### Item
- User scoped
- `boxId` でBoxを参照
- 箱から取り出す操作は `boxId=UNASSIGNED`

### BoxLocation
- User scoped independent flat master
- Box : BoxLocation = many-to-one
- `boxId`を持たない
- hierarchyを持たない
- reserved `UNASSIGNED` を持つ

## 3. Sync metadata
Box / Item / BoxLocationは少なくとも以下のserver sync metadataを持つ。

```text
createdAt
updatedAt
deletedAt
serverUpdatedAt
revision
contentHash
syncSeq
```

client business timestampはconflict winner、Pull order、cursor、retention判定に使用しない。

## 4. Delete
deleteはtombstone。

- Item delete: Itemをtombstone化
- Box delete: child ItemsをUNASSIGNEDへ移動してBoxをtombstone化
- BoxLocation delete: child BoxesをUNASSIGNEDへ移動してBoxLocationをtombstone化

親deleteとchild補正はserverの同一論理transactionで行う。

## 5. contentHash
SHA-256を使用し、entity typeごとの固定business schemaをcanonicalizeして計算する。

除外:
- id / userId
- metadata timestamp
- revision / syncSeq
- contentHash自身

含む:
- business content
- active/deleted state

文字列は用途に応じtrim + NFC。tagsはtrim + NFC、empty除去、exact dedupe、case-sensitive、deterministic sort。required referenceはnull/emptyを許さず未設定はreserved `UNASSIGNED`。

## 6. server auxiliary model
設計上必要:
- SyncChangeLog
- SyncConflict
- Device / DevicePrefix
- Restore lock
- RestoreApplyResult

local側:
- Business
- SyncState
- Outbox
- Full Resync staging
- RestoreApplyMarker

## 7. 設計残件
- Box / Item / BoxLocationの最終field schema
- Outbox / SyncState / SyncConflict / SyncChangeLogの最終field schema
- server unique/index/FK制約
- IndexedDB schema/version/migration
- Restore関連最小schema
- BoxLocation同名後勝ちauto-rename方針の最終再確認
