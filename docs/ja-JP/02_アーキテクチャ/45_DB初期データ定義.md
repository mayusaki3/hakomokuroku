# DB初期データ定義（v0.8）

本書は、v0.8 の新規データベース作成時に投入するシステム初期データと、`prisma/seed.js` の責務を定義する。

v0.8 は旧DBとの互換を持たない初回リリースとして扱い、旧開発環境用の初期ユーザー、初期Box、初期タグ、Vision設定は引き継がない。

---

# 1. 基本方針

DB seed は、ユーザーに依存しないシステム初期データだけを投入する。

ユーザー登録によって生成されるデータや、アプリケーションの既定値で表現できるデータは seed しない。

`seed.js` は複数回実行しても同じ状態になるよう冪等に実装する。

---

# 2. SyncSequence

DB全体で単調増加する `syncSeq` の採番状態として、`SyncSequence` を1件だけ作成する。

| フィールド | 初期値 | 説明 |
|---|---:|---|
| `id` | `"GLOBAL"` | DB全体で使用する固定ID |
| `lastSeq` | `0` | まだ同期変更が発生していない状態 |

既に `id="GLOBAL"` が存在する場合、seed の再実行によって `lastSeq` を `0` に戻してはならない。

---

# 3. seedしないデータ

## 3.1 User

開発用の `dev` ユーザーは作成しない。

ユーザーは通常のユーザー登録処理によって作成する。テストでユーザーが必要な場合も、各テストが必要な状態を明示的に作成し、seedへの依存を避ける。

## 3.2 Box / Item / BoxLocation

初期の Box、Item、BoxLocation は作成しない。

`UNASSIGNED` は未割当状態を表す予約参照値であり、`id="UNASSIGNED"` の実Boxレコードは作成しない。

Item がどのBoxにも所属していない場合は、Item側の設計に従って `boxId="UNASSIGNED"` を使用する。

Box がトップレベルかつ物理的な場所が未設定の場合は、Box側の設計に従って `locationId="UNASSIGNED"` を使用する。

ネストされたBoxでは `parentBoxId` を設定し、`locationId=null` とする。

## 3.3 Tag

v0.8 では独立した Tag テーブルを使用しないため、初期タグは作成しない。

Box / Item のタグは各Businessデータ内の `tags` として保持する。

## 3.4 Vision / LLM設定

Vision機能はv0.8の対象外であるため、Vision用の初期設定やプロンプトは作成しない。

## 3.5 Theme / UserSetting

ThemeおよびUserSettingはグローバルなseed対象としない。

組み込みテーマの既定値はアプリケーション側で提供する。ユーザー固有の設定レコードが必要な場合は、ユーザー登録処理または設定保存処理の責務として生成する。

---

# 4. seed.js の処理

`prisma/seed.js` は次の処理だけを行う。

1. `SyncSequence` の `id="GLOBAL"` を検索する。
2. 存在しない場合は `lastSeq=0` で作成する。
3. 既に存在する場合は変更しない。
4. Prisma Clientを正常に切断する。
5. エラー時はエラーを出力し、非0終了コードで終了する。

---

# 5. テスト要件

seed実装では少なくとも次を確認する。

| Test ID | 確認内容 |
|---|---|
| `DB_SEED-TC-01` | 空DBへのseedで `SyncSequence("GLOBAL", 0)` が作成される |
| `DB_SEED-TC-02` | seedを再実行しても `SyncSequence` が重複しない |
| `DB_SEED-TC-03` | 既存の `lastSeq` がseed再実行によって `0` に戻らない |
| `DB_SEED-TC-04` | User / Box / Item / BoxLocation をseedが作成しない |
| `DB_SEED-TC-05` | 旧TagおよびVision設定に依存するseed処理が存在しない |

テストデータは各テスト自身が準備し、開発用固定ユーザーなどのseedデータを前提としない。

---

# 6. 旧seedからの廃止事項

v0.8への再構築に伴い、次を廃止する。

- `dev` / `dev` の開発用固定ユーザー
- `U_LOCAL` の固定User ID
- `UNASSIGNED` 実Boxレコード
- `保管` / `割れ物` / `電気` の初期Tagレコード
- `visionProvider` およびVisionプロンプトの初期値
- seed済みユーザーを前提とする認証/APIテスト
