# DB初期データ定義（seed.js 仕様）

本書は `prisma/seed.js` を基に、  
**初期投入されるデータの内容と、APIテストでどの値を前提にできるか** を整理する。

---

# 1. 初期ユーザー（devユーザー）

seed.js は開発用に 1 人のユーザーを作成する。

## 1.1 ユーザー情報

| フィールド | 値 | 説明 |
|-----------|-----|------|
| userId | `"dev"` | ログインID |
| passwordHash | `"dev"` （暫定実装） | ※実装のハッシュ方式に合わせて変更予定 |
| totpEnabled | false | 初期状態では無効 |
| totpSecretEnc | null |
| totpPendingSecretEnc | null |
| isActive | true |
| iconDataUrl | null |
| userName | null |

### APIテスト前提
- `/api/auth/login` → email=`dev`, password=`dev` でログインできる  
- TOTP フローは常に「TOTP 無効ユーザーとしての動作」になる

---

# 2. 初期 Box

| 項目 | 値 |
|------|-----|
| name | `"UNASSIGNED"` |
| userId | 開発ユーザーの ID |
| 特記事項 | 最初の箱であり、Box API 実装時の保険用 |

---

# 3. 初期タグ

次の 3 種類が seed される：

- `"保管"`
- `"割れ物"`
- `"電気"`

TagKind は BOX/ITEM を seed.js のロジックに従って設定される。

---

# 4. 初期 UserSetting（Vision設定）

以下の 3 つのプロンプトが初期値として設定される。

- `visionPromptName`
- `visionPromptTags`
- `visionPromptNote`

### メモ
- テストでは通常、Vision 系 API は対象外だが、  
  `/api/settings/user` で設定値が返る場合には seed 初期値を利用する。

---

# 5. 運用方針（テストでの利用）

1. テスト（ユニット/API）では **seed 依存を極力避ける**  
   - テストの独立性のため、必要に応じて事前にユーザー・トークンを生成する
2. 開発環境では `"dev"` ユーザーにより即時ログイン可能  
3. TOTP の有効化テストを行う場合は、  
   - `totpEnabled=false`  
   - `totpSecretEnc=null`  
   の初期状態を前提にテスト開始できる
