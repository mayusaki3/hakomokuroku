# 統合・E2Eテスト方針

## 1. 目的

主要ユーザーシナリオが、UI→API→DB→外部処理まで  
一貫して正しく動作することを保証する。

## 2. 種別

- **統合テスト**  
  API＋Prisma＋テストDB。  
  レコードの永続化と API 間の整合性を確認。

- **E2Eテスト**  
  ブラウザ自動操作で UI から全機能を確認。  
  QR 生成・画像認識などもシナリオに含める。

## 3. 対象シナリオ例

- 箱作成 → QR発行 → アイテム登録  
- アイコン更新 → me API で反映確認  
- 画像アップロード → Vision応答 → Item 登録

## 4. ツール

- 統合テスト：Vitest（API + Prisma）  
- E2Eテスト：将来的に Playwright / Cypress を想定

## 5. 外部サービス扱い

- 画像認識/LLM は、E2E では次のいずれかで対応  
  - テスト用キーで実行  
  - ローカルモックサーバで固定応答  
- コスト・安定性理由で本番キーは使用しない。

## 6. データ管理

- テスト開始前：  
  - migrate  
  - seed データ投入  

- テスト終了後：  
  - クリーンアップ or reseed

- 画像ファイル・QRコードは専用ディレクトリを用意して削除
