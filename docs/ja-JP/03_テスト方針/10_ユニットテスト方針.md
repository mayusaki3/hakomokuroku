# ユニットテスト方針

## 1. 目的と対象

ユニットテストはモジュール単位のバグ検出と、安心したリファクタリングを促進することを目的とする。  
対象は以下の通り。

- ドメインロジック（変換・バリデーション・計算など）
- API Route 内の純粋ロジック（パラメータ解釈 etc.）
- UIコンポーネント（必要に応じて）

## 2. 使用ツール

- テストランナー: Vitest  
- モック: vi.fn / vi.spyOn / vi.mock  
- UI: 必要に応じて React Testing Library

## 3. 配置と命名

- テスト配置: `apps/web/tests/**`  
- API単位で `api.xxx.yyy.spec.ts` の形式でまとめる  
- describe で対象を括り、テスト名は日本語で明確に記述

## 4. モック方針

### 4.1 Prisma

- UT では Prisma を **一切実行しない**。  
- Prisma クライアントをモックした repository / service を差し替える。

### 4.2 API Route ハンドラ

- NextRequest 相当オブジェクトをテスト側で生成し、ハンドラ関数を直接実行。  
- 認証・DB 操作はすべてモック。  
- フォーマットチェック（例: dataURL）は UT で完全網羅。

### 4.3 外部 API

- すべてモック化。  
- ラッパーモジュールを1箇所に集中し、テストではそのラッパーのみ差し替える。

## 5. hook-smoke の扱い

- `api.user.icon.hook-smoke.spec.ts` などの hook 経路確認テストは  
  “モック Prisma 切り替えの回帰テスト” として最低限維持する。  
- Prisma 実DBでの API 統合テストが増えることで、hook-smoke の役割は縮小する。

## 6. デバッグとログ

- 失敗時の原因特定で console.log を使用してよい。  
- 安定後は必要最低限に抑える。
