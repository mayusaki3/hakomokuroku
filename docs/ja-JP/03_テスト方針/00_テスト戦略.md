# テスト戦略

## 1. 目的

本ドキュメントは、箱目録（hakomokuroku）におけるテスト全体の基本方針を定義する。  
以後のユニットテスト・APIテスト・統合/E2Eテストの詳細方針は、本ドキュメントを前提として個別ドキュメントに定義する。

## 2. テストレベル

- ユニットテスト（UT）  
  個々の関数・クラス・コンポーネント・APIハンドラの単位でのテスト。  
  依存コンポーネントはモック/スタブを使用し、挙動と分岐を網羅する。

- APIテスト  
  Next.js API Routes（/api/**）を対象とした HTTP I/F テスト。  
  モックによる「APIユニットテスト」と、Prisma＋テストDBを使用した「API統合テスト」に分かれる。

- 統合テスト / E2Eテスト  
  フロントエンド〜API〜DB〜画像認識/LLM まで含むシナリオの動作確認。

## 3. 対象範囲

- apps/web の UI / hooks / utils  
- /api/** の API Route  
- Prisma を用いたデータアクセス  
- Vision API / LLM / QR ラベル処理

## 4. 品質とカバレッジ方針

- **本番コードのカバレッジは最終的に 100% を目標とする。**
- tests 配下のテストコードはカバレッジ対象外。
- 新規機能の完了条件（DoD）に「テスト実装」および「対象範囲のカバレッジ100%」を含める。
- 本プロジェクトのカバレッジ計測には Istanbul (v8) を使用する。Statements / Branches / Functions / Lines などの各指標は Istanbul の定義に従うものとし、特に Next.js や Prisma の例外分岐など実質的に到達不能なコードが存在する場合は、Branch カバレッジ 100% を必須とはせず、**Lines 100% を優先指標**として扱うことがある（詳細は各 API 方針ドキュメントに記載する）。

## 5. モック / 実リソース利用方針

- Prisma  
  - UT: 完全モック  
  - API 統合テスト: テスト用DB + seed データ

- 外部 API  
  - UT/API: 完全モック  
  - 統合/E2E: テスト用キー or ローカルモック

- QR  
  - UT: 生成/解析ロジック  
  - E2E: 実デバイス利用のシナリオで確認

## 6. テストデータ方針

- テスト用ユーザー・箱・アイテム・タグは seed データとして共通化。
- サンプルデータ仕様は「99_付録/00_サンプルデータ・シナリオ.md」にまとめる。
