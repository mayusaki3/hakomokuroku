# 通知機能概要

## 1. 目的と適用範囲

通知機能は、箱目録で発生した利用者向けの情報を一覧で確認し、必要な操作へ移動できるようにする機能である。

本書は通常通知に共通する基本方針を定義する。通知種別ごとの生成条件、DBフィールド、API入出力、画面部品、テストケースの詳細は各担当仕様書で定義する。現時点で生成条件が確定している通知の例は、Visionの後追い認識完了通知である。その他の通知種別を本書で新たに確定しない。

## 2. 通知と確認状態

- 通知は「未確認」「確認済み」の状態を持つ。
- 通知一覧を表示しただけでは確認済みにしない。個別通知を開いた時点で確認済みにし、確認日時を記録する。
- 確認済みの通知を再度開いても確認日時を更新しない。
- 利用者は期限内の確認済み通知を未確認に戻せる。このとき削除期限を解除する。
- 未確認へ戻した通知を再び開いた場合は、新しい確認日時を記録する。
- 一括確認済み・一括未確認・一括削除に対応する。一括確認済みでは既に確認済みの通知の確認日時を更新しない。
- 通知の確認状態変更は、関連するItemやVision処理の完了状態を変更しない。

## 3. 保存期限と削除

- 未確認通知には保存期限を設けない。
- 確認済み通知は確認日時から30日（720時間）経過した時点で期限切れとする。作成日時は起算点にしない。
- 期限切れ通知は物理削除前でも一覧・件数集計から除外する。個別の詳細取得・状態変更・手動削除は、物理削除済みと区別せず404 Not Foundを返す。
- 期限切れ通知を未確認に戻すことはできない。
- 物理削除はサーバーの定期ジョブで毎日18:00 UTCに実行する。ジョブの停止・失敗によって有効期限を延長しない。
- 利用者は有効な通知を手動削除できる。通知削除は関連するItemの説明・タグやVision認識結果・完了状態を変更しない。
- 定期ジョブの排他制御、ログ、バッチ処理および障害時動作は「通知保存期限と自動削除」に定義する。

## 4. 通知一覧と操作

- 確認状態による絞り込みは「すべて」「未確認のみ」「確認済みのみ」の3種類とし、期限切れ通知はどの条件でも表示しない。
- 並び順は通知作成日時を基準とする「新しい順」「古い順」の切り替えとする。
- 1ページの表示件数は10・20・50・100件から選択でき、初期値は20件とする。
- 絞り込みの初期値は「すべて」、並び順の初期値は「新しい順」とする。
- 表示件数・絞り込み・並び順の設定は端末ごとにローカル保存し、次回表示時に復元する。端末間同期は行わない。
- 通知タイトル・本文のキーワード検索および通知種別による絞り込みは設けない。
- 「全件選択」は現在表示中のページのみを対象とする。ページ移動・表示件数変更・絞り込み変更・並び順変更時は選択をすべて解除する。
- 一括操作は操作可能な通知のみ処理し、期限切れ・削除済みなどの対象外通知はスキップする。利用者には処理件数と対象外件数のみ表示し、個別ID・対象外理由は表示しない。
- 一括削除のみ、実行前に選択件数を示す確認ダイアログを表示する。一括確認済み・一括未確認には確認ダイアログを表示しない。

## 5. Vision後追い認識完了通知

- Vision後追い認識が完了した場合、対象Itemごとに個別の完了通知を作成する。
- 後追い認識結果は利用者の事前承認を待たずにItemへ反映する。説明は未入力の場合に限り反映し、既存タグを維持したまま正規化比較で重複しない新規タグを追加する。
- 通知から対象Itemの編集画面へ直接移動でき、利用者は内容の修正や再認識を行える。
- 通知の確認・削除は、認識結果の反映や認識処理の完了状態を変更しない。
- Vision完了通知にも通常通知と同じ確認状態・保存期限・削除規則を適用する。Vision専用の通知保存期限は設けない。
