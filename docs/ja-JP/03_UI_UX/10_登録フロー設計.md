# 登録フロー設計

## 1. Scope
v0.8標準登録フロー:
`Box -> Items -> Box photo -> Label -> Location -> Complete`

wizard全体を1 transactionとして扱わない。各Business変更は通常local Business + Outbox規則で即時保存する。

## 2. Box step
Box stepでrequired fieldを満たし「次へ」を実行した時点でBoxを作成する。

同一IndexedDB transaction:
- Box create
- Outbox UPSERT
- Box.code LocalSequence increment

成功後のみItems stepへ進む。Box作成transaction失敗時はstepを進めず、code sequenceもcommitしない。

## 3. Items step
Itemは1件ごとに通常create/updateとして保存する。
- Item追加成功後、一覧へ即反映
- 複数Itemをwizard終了まで未保存状態にしない
- 0件でも次へ進める
- stepを戻っても作成済みItemを削除しない
Item削除は通常delete/tombstone規則。

## 4. Box photo step
写真は1枚ごとにPhoto / Blob設計のnormal ingestionで保存する。
- 0枚でもskip/next可能
- 追加済み写真は戻る/cancelで自動削除しない
- 写真削除は通常photo delete + Undo

## 5. Label step
LabelはBusiness save stepではない。preview / print/export / skipのいずれもBox Businessを変更しない。print/export失敗でも登録済みBoxをrollbackしない。

## 6. Location step
Locationはoptional step。初期Boxは `locationId=UNASSIGNED` で成立する。Location選択/作成後の割当は通常Box updateとして保存する。
- skip -> UNASSIGNEDのままComplete
- existing Location選択 -> Box update
- new Location作成 -> BoxLocation create後、Box.locationId update
- save失敗 -> Complete扱いにせずretry/skip可能

## 7. Back
「戻る」はnavigation。
- previous stepへ移動
- 保存済みBusinessをrollbackしない
- previous stepのcurrent canonical local stateを表示
- 修正した場合は新しい通常Business update

PhotoからItemsへ戻っても既存photoは保持される。Item編集は通常update。

## 8. Skip
skip可能:
- Items: 0件で次へ
- Box photo: 0枚で次へ
- Label: 印刷せず次へ
- Location: UNASSIGNEDで完了

Box stepはskip不可。既にdataがあるstepでskipしても既存dataを削除せず、追加操作せず次へ進むだけ。

## 9. Cancel
Box作成前: draft破棄、Business/Outbox変更なし、Device sequence変更なし。

Box作成後:
- 「登録フローを終了」として扱う
- 作成済みBox/Item/photo等を保持
- Boxを自動deleteしない
- pending Outboxも保持
- 通常Box detail/listへ戻る

作成済みBoxを消す場合は別の明示的Box delete操作を使用する。

## 10. Close / reload / crash
Box作成前の未commit form draftはv0.8で永続化保証しない。Box作成後は各stepが即時保存なのでreload/crash後もBusinessは保持される。wizardの現在stepをBusiness correctness上の必須persistent stateにしない。再開時はBox detailから必要操作を継続できる。

## 11. Offline
healthy DeviceStateにcode発行余地があれば全registration Business stepをoffline実行可能。Device prefix exhaustedでonline allocation不能の場合はBox stepで新規Box作成のみblockする。

## 12. Sync
wizard完了をPush条件にしない。保存されたBusiness/Outboxは通常Sync対象。wizard途中でもnetwork条件が整えばSync可能。SyncConflictでもwizard全体をrollbackしない。

## 13. Complete
Location stepのnextまたはskipでComplete。Completeは新しいBusiness transactionではなくUI state。完了後はBox detailへ遷移しlocal sync stateを表示可能。`完了済み` Business flagは追加しない。

## 14. Destructive confirmation
Back/Skip/Cancelではdestructive confirmation不要。保存済みBusinessを削除しないため。明示delete/photo delete等だけ通常delete UI規則に従う。

## 15. Design complete
登録フローのnavigation/save boundaryは確定。
